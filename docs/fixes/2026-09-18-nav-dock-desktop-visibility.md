# 2026-09-18 悬浮导航在桌面端调试仍不可见的修复

## 问题

上一轮修复后,用户在桌面端浏览器控制台调试仍看不到悬浮球,油猴菜单点击也
"打不开"悬浮导航栏。

## 根因定位

`applyMobileNavDock` 的激活条件为
`isMobileNavDockEnabled() && isRepoHomePath() && isMobileDevice()`:

1. **桌面端被设备门槛刻意拦截**:桌面环境(无触摸、桌面 UA、宽窗口)三个
   `isMobileDevice` 子条件全不满足,每次构建前都 `removeNavDock()` —— 这是
   设计残留,不是渲染缺陷。功能定位是"移动端悬浮导航",但调试与可见性验证
   被同一门槛挡住。
2. **菜单点击反馈错位**:菜单回调固定发"已开启/已关闭"通知,与悬浮球是否
   真的出现在页面上无关;桌面端开关后页面无变化,通知文案却称"已开启",
   用户感知即"点了没效果"。

## 修复方案

1. 快照检查点 `a540451`。
2. **取消设备门槛**:激活条件简化为"功能开启 + 仓库主页路径"
   (`isMobileNavDockEnabled() && isRepoHomePath()`)。所有设备(含桌面)的
   `/:owner/:repo` 主页都渲染悬浮球;移动端优先的样式(左下角 FAB + 面板)
   保持不变,桌面端同样可用、便于控制台调试。删除 `isMobileDevice()`。
3. **菜单通知与实际渲染状态对齐**:重建后检查 `NAV_DOCK_TOGGLE_ID` 是否真实
   存在于页面,据此发送"已开启(可见)/已关闭/已开启但当前页面不是仓库主页"
   三种文案;不可见原因同时输出到控制台。
4. 面板开关与控制台诊断逻辑同步更新。

## 验证

- `node --check` 语法通过(0 错误)。
- 全文检索确认 `isMobileDevice` 引用清零,激活条件仅剩 开关 + 路径。
- git diff 复查:通知三分支完整、诊断信息包含 path/repoHome/enabled。
- 桌面验证路径:访问任意 `github.com/:owner/:repo` 主页 → 左下角应出现
  悬浮球;油猴菜单切换 → 应收到与页面实际状态一致的系统通知。
- 本仓库为纯用户脚本,无 release/debug 构建配置,以语法检查 + diff 复查替代
  双构建验证。
