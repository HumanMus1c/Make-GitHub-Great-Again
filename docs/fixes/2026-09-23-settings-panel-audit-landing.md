## 3. 逐条修法

### 3.1 §1.1 + §1.6：关键词容器"先下沉、再隔离"（两条必须一起做）

这两条落在同一个元素上，顺序不能反：

```css
#customKeywordsContainer {
  /* 原来是模板内联：style="max-height: min(16em,28vh); overflow-y:auto; margin-bottom:.5em" */
  max-height: min(16em, 28vh);
  overflow-y: auto;
  margin-bottom: 0.5em;
  overscroll-behavior: contain;   /* §1.1 */
}
```

- 内联样式优先级高于任何样式表规则，**不先下沉就没法统一**：主题化、滚动条规则、响应式
  全都会"改了没反应"（§1.2 是同一个坑的另一处实例）。
- 下沉之后它才是一个"可被样式表描述"的**独立滚动宿主** —— §2.2 的滚动条规则才有地方挂。
- `overscroll-behavior: contain` 的理由是实测的：该容器**真的溢出**（内容 456px / 视窗
  168–224px），而改前是 `auto` ⇒ 鼠标停在里面滚到底，滚动会继续传给**外层内容区**
  （同脚本里导航面板条目区用的是 `contain`，两处行为本来就不一致）。

  **⚠️ 这里更正了审计文档的一处推断**：原文写的是"滚动会继续传递给外层/页面"，
  实测**页面那一层根本轮不到** —— 祖先链是 `kw → .color-picker-content → 页面`，
  而内容区自己早就带着 `overscroll-behavior: contain`，它在中间就拦住了。
  单独跑一支探针（`.workbuddy/probe/diag-wheel-chain.js`，视口压到 1280×520 逼面板限高、
  内容区必然溢出）量到的真相比原文更精确：

  | 1280×520，列表滚到底再多滚 10 轮 | 改前 | 改后 |
  | --- | --- | --- |
  | 关键词列表 `scrollTop` | 0 → 771（到底） | 0 → 771（到底） |
  | **内容区** `scrollTop` | 0 → **7**（被带动） | 0 → **0** |
  | 页面 `window.scrollY` | 0 | 0 |

  7px 只是"探针里内容区刚好只溢出 7px"（`scrollH 407 / clientH 400`）的结果；
  真实场景下内容区溢出多少就会被带走多少。**结论不变、承接者变了**：
  改这条不是为了让页面不乱滚（页面本来就不乱滚），而是不让"看关键词列表"顺带把整个面板的内容区滑走。

### 3.2 §1.2：把内联的 `margin-top` 收进 CSS（视觉零位移）

模板里 `<div class="button-row" style="margin-top: 1em;">`，而 CSS `margin-top: 0.75em`
—— 内联胜出，于是"改 CSS 调间距"一直无效。删内联后**把那个 1em 收进 CSS**，
`padding-top: 0.35em` 保留 ⇒ 1.35em 与改前逐字一致，真机复测 gap 未变。
（不是"顺便把间距调小到 0.75em"：那是需求外的视觉改动。）

### 3.3 §1.4：删除三条永不适用的取色库适配

JS 侧 `panel._pickr` / `_huebee` / `_spectrum` **全文只被读取、从未赋值**，
`window.Pickr` / `Huebee` / `$` 也没有任何加载逻辑 ⇒ 三个 `if` 恒不执行；
样式表侧 `.pcr-app` / `.huebee` / `.sp-container` 同样永不生效。

删除时踩到一个**自己给自己挖的坑**：第一版把这些标识符写进了"已删除"的注释里，
于是 `grep` 型检查仍然命中 —— 注释等于把死代码"留在原地"。改成中文描述后，
11 个字面量（含三条 CSS 选择器）全文 0 残留，闸门才能做"全文不含"这种强断言。

保留 `#libraries-container`：名字像"库容器"，实际是**内置取色器的挂载点**
（`initializeLibraries` 往里写 canvas 取色器），不是死代码。

### 3.4 §1.5：行节奏统一到颜色块那一档

行高由"行内最高的子项"决定：带颜色块的行走 `.color-button`（0.8em 字号 × 2em = 1.6em
≈ 22.39px），不带色块的行走 `.color-toggle-btn`（0.8em × 1.8em ≈ 20.16px）。

```css
.color-picker-row { min-height: 1.6em; }   /* = 颜色块那一档 */
```

刻意**不动按钮自身尺寸**（那会牵动标题栏/悬浮球那套成对闸门）；`align-items: center`
保证变高后内容仍垂直居中。代价是面板总高 +2.78px（两行各 +1.39px），属预期。

### 3.5 §1.3：三颗按钮换 Primer 语义色（含深色档）

改前是 Bootstrap 时代的亮蓝/亮橙/亮红，且**没有任何深色变体**；语义还是反的
（"确认"用橙、"取消"用蓝）。现在：

| 按钮 | 语义 | 浅色档 | 深色档 |
| --- | --- | --- | --- |
| 确认 | primary | `#1f883d`（hover `#1a7f37`） | `#238636`（hover `#29903b`） |
| 取消 | neutral | `#f6f8fa` + `inset 0 0 0 1px rgba(31,35,40,.15)` | `#21262d` + `inset … rgba(240,246,252,.10)` |
| 重置 | danger | `#cf222e`（hover `#a40e26`） | `#da3633`（hover `#f85149`） |

两个细节：

- **取消按钮的描边用 `inset box-shadow` 而不是 `border`**：`border` 占盒模型，会让这颗
  按钮比另两颗高 2px。上一轮刚把面板间距调准，这里不做几何位移。
- **配色只写在两个 `prefers-color-scheme` 块里**，基座不写：写在基座会盖住深色档
  （同权重时按源码顺序，而基座在前）。这也与对话框既有的"主题走媒体查询"机制一致 ——
  它走的是老一套 `prefers-color-scheme`，**不能引 GitHub 变量**（会出现浅色对话框 + 深色变量错配）。

### 3.6 §2.1：面板尺寸与悬浮球同源自适应

改前面板字号是 `--mgga-text-scale: 1em` 定值 ⇒ 宽恒为 `20em = 280px`；而悬浮球上一轮已改成
`clamp(38px, 4.4vmin, 56px)` ⇒ **4K 全屏下球长到 56px、面板纹丝不动**，两者脱节。

```css
:root { --mgga-panel-font: clamp(14px, calc(0.735vmin + 7.41px), 18px); }
.color-picker-dialog { font-size: var(--mgga-panel-font); }
```

面板内所有尺寸都是 `em` ⇒ **只改这一个字号**，宽度/行高/间距/滚动条随之同比缩放。
取值刻意让 1280×896（vmin 896）落在 **14px —— 与改前逐字相同**，即"小屏观感零变化"，
只在大屏上生长；1440p 及以上封顶 18px（面板 360px）。

### 3.7 §2.2：滚动条规则抽公共段（单一来源）

改前只有导航面板配了滚动条样式（10 余条手写规则，含 Firefox 的 `@supports` 兜底），
设置面板**一条都没有** ⇒ 在"始终显示滚动条"的环境（或 Firefox）里两处观感打架。

新增模块级生成器：

```js
function immersiveScrollbarCss(hosts, hoverHost) { … }
```

- 导航面板：`immersiveScrollbarCss(["#mgga-nav-dock .mgga-nav-dock-body"], "#mgga-nav-dock")`
- 设置面板：`immersiveScrollbarCss([".color-picker-dialog .color-picker-content",
  ".color-picker-dialog #customKeywordsContainer"], ".color-picker-dialog")`

两处差别只剩宿主选择器与 hoverHost。**必须同步搬迁的还有断言**：规则一旦变成运行时生成，
旧闸门在 `injectNavDockStyle` 切片里就找不到那段文本 ⇒ 会假红。新断言改为
"生成器里有没有 + 调用点传对宿主没有"，并加一条"切片内不得再出现手写 `::-webkit-scrollbar`"
守卫单一来源。

## 6. 判据沉淀

- **"规则搬进运行时生成器"必须同时搬断言**：源码级闸门锁的是源码字符串，规则一变
  生成，旧断言就在切片里找不到那段文本、直接假红 —— 而"假红"会被误读成改动出错。
  本次把滚动条闸门从"源码里有没有这段 CSS"改成"生成器有没有 + 调用点参数对不对"。
- **删死代码时，注释里不要留它的字面量**：写在"已删除"注释里的标识符会让 grep 型检查
  依旧命中，等于死代码没删干净；改用中文描述才能做"全文不含"这种强断言。
- **同一元素上的"下沉 + 行为修正"有顺序**：内联样式不下沉，任何样式表规则都改不动它。
- **改观感时优先用不占盒模型的属性**：取消按钮的描边用 `inset box-shadow` 而非 `border`，
  三颗按钮高度因此逐字不变，不必重新取证面板几何。
- **探针里的破坏性步骤（塞满内容、改 DOM）要排在所有测量之后**：否则会污染后续档位。
- **"没测出差异"要先怀疑测试条件，而不是认定改动无效**：1280×896 下内容区不溢出，
  §1.1 的接力根本没机会发生 ⇒ 两支脚本量到的 `window.scrollY` 都是 0。压到 1280×520
  逼出溢出条件后，改前的承接行为（内容区被带动）才显形。
- **审计结论里"传给外层/页面"这类措辞要落到具体承接者**：祖先链上任何一层带
  `overscroll-behavior: contain` 都会截断接力，笼统写"页面"会让人以为改这条是为了防整页乱滚。
