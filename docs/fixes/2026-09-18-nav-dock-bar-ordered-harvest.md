# 2026-09-18 收割项按栏归位排序与视口感知缓存

## 需求

1. 文件区只收到 README 一项,其余项缺失且排序位置不对。
2. 桌面端切移动端调试时,GitHub 把放不下的项挪进 More 二级列表,可见项
   从 10 个缩到 5 个,面板随之缩水。

## 根因定位

1. **排序不对**:旧实现把所有栏的 More 收割项统一追加在面板末尾。实际
   DOM 顺序是"标签条可见项 → 标签条 More 溢出项 → 文件区 README →
   文件区 More 溢出项",统一尾部追加导致 Settings/Security 等溢出项与
   文件区项交错、位置错乱。
2. **收割不完整**:文件区 More 收割发生在注水前轮次时拿到空结果且不入
   缓存,但若注水前首轮恰好点开了触发器收割到部分项,后续轮次命中路径
   级缓存就不再补收;按栏收割后每栏结果独立缓存,注水后桶变化/重建会
   重新收割缺失栏。
3. **视口缩水**:收割缓存键只有路径。桌面切移动端后 GitHub 重排可见集
   (10 → 5),可见项集合变化,但缓存仍命中旧键,More 里新增的 5 个溢出项
   永远不会被补收。

## 修改方案

1. 快照检查点 `9924d58`。
2. **按栏收割 + 按栏归位**:收割循环改为 `Map<barKey, items>`,
   `navBarKey` 用 aria-label + 类名前缀稳定标识栏;`collectRepoHomeNavItems`
   在遍历每栏时把本栏收割项紧跟本栏可见项之后插入,还原真实导航顺序。
3. **视口感知缓存**:缓存键 = `pathname + "#" + viewportBucket`,
   桶宽 100px;resize/orientationchange(已有监听)后桶变化即重收割。
   空收割不写缓存的语义保留;按栏非空才缓存,避免污染。
4. 逻辑单测:bar1 可见项 + bar1 收割项 + bar2 可见项 + bar2 收割项,
   输出顺序 Code > Issues > Pull requests > Settings > Security > README,
   符合"溢出项紧跟本栏"的预期。
5. 版本 2026.9.28,update_log 同步。

## 验证

- `node --check` 语法通过(0 错误)。
- 顺序模拟单测 PASS;diff 复查:navBarKey/viewportBucket 新增、按栏归位
  插入、缓存键升级、Map 化收割四处改动与计划一致;缓存命中路径不再触碰
  触发器,防重复点击语义保留。
- 本仓库为纯用户脚本,无 release/debug 构建配置,以语法检查 + 逻辑单测 +
  diff 复查替代双构建验证。
