## 1. 改前的状态

面板里散落着 5 类 unicode 状态字形，全部由**系统字体渲染**：

| 位点 | 字形 | 盒子尺寸靠什么 | 换 SVG 是否动几何 |
| --- | --- | --- | --- |
| 5 个开关按钮 | `✓`（启用）/ `✕`（停用） | `.color-toggle-btn` 是 `width/height: 1.8em` **定值** + flex 居中 | **不动** |
| 关键词操作按钮 | `×`（删除）/ `↩`（恢复） | 父项 `inline-flex`，自身 `line-height: 1` | 不动（见 §3.2） |
| 内置取色器「清除」 | `✕` | `.builtin-clear-btn`：`font-size: .85em` + padding 撑高 | **会变** |
| 设置面板关闭控件 | `✕` | `14px` + `line-height: 1.2` + `padding: 2px 6px` 撑高 | **会变** |
| 导航面板关闭控件 | `✕` | 同上（成对标准） | **会变** |

问题不在「难看」，而在**不可控**：字形的粗细、基线、字面大小（以及是否被 fallback 字体
接管）都由系统与字体决定，与已经 SVG 化的悬浮球（`FAB_GEAR_PATH` + `gearIconSvg()`）、
导航项图标（`ICON_PATHS` + `buildNavDockFallbackIcon`）不是同一套视觉语言。
关键词那处更离谱 —— 删除用**乘号** `×`（U+00D7）、恢复用**弯箭头** `↩`（U+21A9），
两个字符的语系、字面大小、垂直位置都不相关。

## 2. 唯一真风险：盒高

关闭控件是各自标题栏里**最高的子项**，而标题栏高度 = `max(子项高) + 上下 padding + 下边框`。
这条线用户已经核对过两次（`docs/fixes/2026-09-23-titlebar-*` 系列），且有两条闸门锁死。
它的高度来源是：

```
14px(font-size) × 1.2(line-height) + 2px×2(padding) = 20.8px
```

⇒ 换成 SVG 后**必须让行盒高度仍由 `line-height` 决定**。具体就是图标只能留在行内盒：

- ✅ `vertical-align: middle`（本项目采用）
- ❌ `display: block` —— 行盒会塌成图标自身的 `1em`，按钮与两处标题栏一起矮 **2.8px**

清除按钮同理（`0.85em` + padding 撑高）。开关按钮无所谓（定值盒 + flex 居中，
`vertical-align` 对它无效但无害）。

## 3. 改法

### 3.1 基建（一处单一来源）

在 `GITHUB_MARK_PATH` / `FAB_GEAR_PATH` 同一区域新增：

- `UI_ICON_CHECK_PATH` / `UI_ICON_X_PATH` / `UI_ICON_UNDO_PATH`
  —— 路径**不手写**，取自 `@primer/octicons` 官方 16px 数据（`check-16` / `x-16` / `undo-16`）。
- `UI_ICON_PATHS` 映射表 + `uiIconSvg(kind)` 字符串生成器（`kind: check | x | undo`）。
  与 `gearIconSvg()` 同范式：**不写 `width/height` 属性**，尺寸交给 CSS 的 `1em`。

尺寸走 `1em` 的好处是「一条规则跟随四处不同字号」—— 开关按钮 `0.8em` 基准、
关闭控件 `14px`、清除按钮 `0.85em`、关键词按钮 `0.9em`，全部自动正确，不必逐处写死像素。

### 3.2 调用点（11 处）

| # | 位置 | 改动 |
| --- | --- | --- |
| 1–5 | `buildSettingsDialogHTML` 里 5 个开关按钮模板 | `>✓</button>` → `>${uiIconSvg("check")}</button>` |
| 6 | 设置面板关闭控件模板 | 同上，改 `uiIconSvg("x")` |
| 7 | 内置取色器「清除」按钮模板 | 同上，改 `uiIconSvg("x")` |
| 8 | `bindFeatureToggleButtons` 的 `paint` | `on ? "✓" : "✕"` → `on ? uiIconSvg("check") : uiIconSvg("x")` |
| 9–10 | `updateToggleBtnUI` 的两个分支 | 同上 |
| 11 | 关键词条目的 `actionIcon` | `pendingDelete ? "↩" : "×"` → `uiIconSvg(pendingDelete ? "undo" : "x")` |

导航面板关闭控件原本走 `closeBtn.textContent = "✕"`，改成 `closeBtn.innerHTML = uiIconSvg("x")`
—— `textContent` 装不下 SVG，这是把 `textContent` 换成 `innerHTML` 的唯一一处。

### 3.3 样式（一条规则）

```css
.color-toggle-btn > svg,
.builtin-clear-btn > svg,
.color-picker-close > svg,
.custom-keyword-item .keyword-action-btn > svg,
#mgga-nav-dock .mgga-nav-dock-close > svg {
    width: 1em;
    height: 1em;
    vertical-align: middle;
}
```

写在设置面板那份注入样式表里（`GM_addStyle` 是全局作用域，导航面板的元素一并命中，
不必两处各写一份）。

### 3.4 注释清理

样式表里那段描述「原来是个 `<span>×</span>`」的注释已过时，改写成现状 + 新约束
（**图标必须留行内**）。同时把注释里残留的 `✕` / `✓` 字面量清掉 —— 按项目既有教训，
注释里留着字面量会让「全文不含某字形」这类最强断言失去意义，等于没删干净。

**宽度会变，这是换图标的必然代价**（表里只列两侧都变的项）：

| 指标 | 改前 | 改后 | 说明 |
| --- | --- | --- | --- |
| 关闭控件盒 w（两处） | 23.44 | 26（**两处同步 +2.56**） | 成对性未破 |
| 清除按钮盒 w | 25.98 | 28.14（+2.16） | — |

原因：octicon 画在 16×16 网格里、按 `1em` 渲染（关闭控件处即 14px 见方），而原字形
`✕`（U+2715）的字面宽度只有约 9.4px。要抹平这点宽度只能把图标缩到 `0.67em` 上下，
那样图标会明显小于所在文字，得不偿失，故不做。**成对标准（两处关闭控件）仍然同步。**

**图标尺寸 = 各处的 1em**（改后实测，证明「尺寸跟随字号」这套确实生效）：

| 位点 | 基准字号 | svg 实渲染 |
| --- | --- | --- |
| 开关按钮 | 0.8em | 11.19 |
| 关闭控件 | 14px | 14 |
| 清除按钮 | 0.85em | 11.89 |
| 关键词操作按钮 | 0.9em | 12.59 |

**图标身份**（按 path 前 24 字符核对，证明换的是"正确的"那一枚）：

| 位点 | 改后 path 前缀 | 对应 octicon |
| --- | --- | --- |
| 关闭控件 / 关键词删除按钮 | `M3.72 3.72a.75.75 0 0 1` | `x-16` |
| 关键词「待删」恢复按钮 | `M1.22 6.28a.749.749 0 0` | `undo-16` |

另：关闭控件的 `textContent` 由 `"✕"` 变为 `""`（纯图标，无障碍名仍由 `aria-label` 提供），
关键词「待删」态确实切到了 undo 图标 —— 即开关态与待删态**都**验到了，不是只看默认态。

### 4.3 探针踩的两个坑（留给后续复用）

1. **`eval(HELPERS)` 在 `page.evaluate` 里必然失败** —— `HELPERS` 是 Node 侧变量，
   `page.evaluate(fn)` 只序列化函数本体，页面里没有这个标识符（报 `HELPERS is not defined`）。
   小工具函数必须**内联写进每个被测函数体内**。
2. **导航球只在仓库主页出现**，Release 页上冒出的是设置球 —— 想量导航面板必须单独
   `goto` 仓库主页并**重新注入脚本**（换了文档，之前注入的脚本不会自动跟过去）。
