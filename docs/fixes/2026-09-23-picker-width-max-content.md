## 1. 根因（一句话）

取色器子面板是 `width: max-content`，宽度由**内容固有尺寸**决定；而它的取色容器写着
`width: min(250px, 100%)` —— 在固有尺寸计算那一遍**包含块宽度不定、百分比按 `auto` 处理**，
所以那个 `100%` 等于不存在，声明退化成「容器取内容固有尺寸」；容器里每个
`<input type="text">` 不带 `size` 时固有宽按**默认 20 字符**计，切到 RGB/HSL 一下多出**三个**数字框，
各把 max-content 撑大 ≈165px ⇒ 面板被撑到 605.67px。定尺之后真正排版那一遍把容器算回 250、
三个框正常均分 47.63，但**面板宽度不会重算** ⇒ 多出来的 331.28px 永久空着。

## 2. 取证（改前，iina/iina，1280×896）

| 色值格式 | 面板 rect 宽 | 取色容器 rect 宽 | 面板内容盒右缘 − 容器右缘 |
| --- | --- | --- | --- |
| HEX | 281.17 | 250 | 6.78 |
| RGB | **605.67** | 250 | **331.28** |
| HSL | **605.67** | 250 | **331.28** |

**关键判据**：三种格式下 `.builtin-input-group` 的实际布局**逐字相同**（227.63）——
说明「面板被撑宽」而不是「内容被挤开」。数字闭合：605.67 − 0.8em×2(22.4) − 边框 2 − 250 = **331.27**
（实测 331.28）；HEX 档同式 256.77 − 250 = 6.77（实测 6.78）⇒ **HEX 档早就有同类毛病，只是小到看不出来**。

**介入实验**（在真机页面就地改一处内联样式/属性，量一次即还原；这是定案的关键一步）：

| 实验 | 改动 | 面板宽 | 容器宽 | 右侧留白 |
| --- | --- | --- | --- | --- |
| E1 | 容器内联 `width: 250px` | **274.38** | 250 | −0.01 |
| E2 | 三个数字框加 `size="3"` | **274.47** | 250 | 0.08 |
| E3 | **只**给第一个框加 `size="3"` | 486.67 | 250 | 212.28 |
| 还原 | — | 605.67 | 250 | 331.28 |

E3 证明「虚宽来自每个输入框各自的固有尺寸」：修掉一个，留白 331.28 → 212.28（−119.0）；
三个全修则归零。两种候选修法最终都落在 274.4（= 250 + 22.4 + 2）。

## 3. 改了什么（一行）

```diff
 .builtin-color-picker-container {
     …
-    width: min(250px, 100%); /* 常规固定宽度，窄屏时收缩 */
+    width: 250px;            /* 必须是定值：见上方注释，定值才不给 max-content 祖先留漏 */
     max-width: 100%;         /* 窄屏收缩仍由它负责（百分比在固有尺寸那一遍按 none 处理） */
     box-sizing: border-box;
 }
```

配套：`tools/smoke-load.js` 新增源码级闸门
**「取色器容器宽度是定值（不给 max-content 祖先留漏）」**（断言规则体里有 `width: 250px;`
与 `max-width: 100%;`、且**不含** `min(250px…)`；断言前先剥掉注释，免得注释里的字样自伤）。

**为什么改容器而不改输入框**：输入框那条路要动四处（三个 `size` + HEX 框 `size`），
且修完的 274.47 依赖「三个框固有宽恰好仍 ≥250px」这个巧合（实测 250.07）；
容器改定值后，面板宽度**恒等于**「容器 + 内边距 + 边框」，与内部输入框的固有宽度**彻底解耦**。

## 6. 顺带发现（**本次未改**）

`picker-input-cascade.json` 显示：`.builtin-color-value-input` 的
`width: 0 / padding: 0.3em 0.2em / font-size: 0.85em / font-family: 'Courier New'`
与 `.builtin-color-hex-input` 的 `padding: 0.3em 0.5em / font-size: 0.85em / font-family: 'Courier New'`
**从未生效** —— 被 `.custom-color-picker-panel input[type="text"]`（特异性 (0,2,1) > (0,1,0)，
且在样式表中更靠后）整条拿下。计算值对账：数字框实测 `font-size: 12.6px`（= 0.9em × 14px）、
`padding: 3.78/5.04px`（= 0.3em/0.4em），未渲染时 `width` 读作 `100%`。
**这次用户只选了「只改容器宽度」，故这些死声明原样留着**；将来若要清理，注意删掉后
这三个框的字号会从 0.9em 掉到 0.85em、内边距变窄 —— 那是**可见的观感变化**，不是无条件收益。
